
第四章 SQL 与 NoSQL 语义分析与维护 
 问题描述 
在上一章中，文章通过设计面向多源异构数据库的统一语法解析器，实现了解析语法的动
态扩展。然而，语法解析仅实现了对语句的语法层面分析，无法判断语句是否真正有意义。
因此在语法分析器生成 AST 后，下一阶段就是语义分析与验证。这一阶段负责检查 AST 的
语义正确性，如表和列的存在性、数据类型的一致性、函数和表达式的有效性等，生成一个
能够描述逻辑执行计划的语义模型。如果发现语义错误，则抛出语义错误异常，并生成报告。 
然而传统的数据库语义分析方案已经无法满足复杂多变的业务需求：①传统的语义分析
方案仅针对特定的数据库系统或 SQL 方言进行设计，缺乏跨数据库和跨平台的灵活性。当面
对不同的数据库系统或新的 SQL 特性时，传统方案往往需要进行大量的修改和重构，不仅增
加了开发成本，还降低了系统的可维护性；②此外，随着数据库技术发展，新的查询语法和
特性层出不穷，传统语义分析方案往往难以适应这些变化，缺乏可扩展性；③传统的语义分
析方案仅能进行简单的语法验证，而忽略了对查询语义的深入分析，可能导致一些语义上错
误的查询被执行，从而引发数据错误或逻辑错误。 
本章的语义分析方案采用模块化设计，使开发者能够以统一方式对 SQL 指令的语法语义
信息进行处理，仅对特定业务进行扩展，降低重复开发成本。语义分析器能够将不同的 SQL
方言标准化为统一的查询模型，简化了跨数据库查询的过程，并适应不断变化的数据库技术
和新的 SQL 特性。 
需要补充说明的是，如 MongoDB 和 Cassandra 等 NoSQL 数据库，使用更加灵活的数据
模型，通常不需要复杂的关键数据采集步骤；并且在语法方面，NoSQL 规避了 SQL 查询严格
的语法规则，采用更简单、更灵活的指令形式。这意味着它们不需要像 RDB 那样进行严格的
模式匹配和语义验证，仅需要进行一定形式的数据验证，保证数据的完整性和一致性。

4.2.1 中间表示模型总体设计 
由于不同数据库系统的数据存储模型不同，在数据命名、数据类型、数据结构方面存在差
异，需要设计不同语法模型之间的转换策略。如图 4.1(a)所示的传统多对多转换模式，两个异

n*(n-1)个数据转换器。如果新增一个可迁移数据库类型，则需要新开发 2n 个转换器，导致开
发维护成本高、扩展性差。

4.2.2 Expression 实体设计 
Expression 包含 SQL/NoSQL 语法中的筛选条件、表达式、字段、常量等元素，也包含 SQL
中很多（如子查询、联接、聚合函数等）既包含语句成分也包含表达式成分的元素，是数据
库执行过程中的重要参数。对 SQL/NoSQL 语法的语义分析，其主要工作在于对 Expression 部
分内容进行元数据提取与校验，因此将 Expression 中间表示的设计独立划分出来。Expression
语义实体以 SQL 语法描述为中心，而后逐步引入 NoSQL 的表达式语义的支持和转换，因此
本节以 SQL Expression 语法为基础讲述。 
在 SQL 语法中，Expression 实体按照使用场景和表示内容，可以分为：compdExpr
（compound expression,复合条件式）、valueExpr（value expression,常量）、idExpr（identifier 
expression,标识符）等类型，便于语义分析器分情况验证。 
 Expr = compdExpr ∪ valueExpr ∪ idExpr (4.2) 
（1）复合表达式 
compdExpr 实体由多个子表达式通过运算符组合的多元表达式集合，根据在编译器中的
执行优先级，可划分为逻辑表达式、关系表达式、计算式或子查询（如 exists、in 子句）等内
容。compdExpr 的语义结构化描述如下： 
compdExpr = {〈exprs, opc
, priority〉| exprs = {expr1, expr2, ⋯ expri
} ⋀ expri ∈ Expr 
⋀ opc ∈ BOP ⋀ priority > 0 } 
(4.3) 
在这个定义中，exprs 是一个 list，包含组成复合表达式的子表达式{expr1, expr2, ..., expri}
（i>=2）；BOP（Binary Operator）是复合表达式中的运算符集合，包含逻辑运算符（如
AND/OR/NOT）、关系运算符（如>，<，=，!=）、算术运算符（如+-*/）等，也包含 BETWEEN、
EXISTS、IN 等关键字；priority 是一个正整数，用于描述该复合表达式在 SQL 编译器中的优
先级，决定了表达式求值的顺序。由 3.3.1 可知，compdExpr 在 SQL 中根据过滤、计算或转
换等作用，存在语义规则： 
∀expr ∈ compdExpr → expr ∈ (logicExpr ∪ booleanExpr ∪ relExpr) 
⋁ expr ∈ (calcExpr ∪ funcExpr) 
(4.4) 
即对于任意 compdExpr 类型的 expr，要么是 logicExpr（逻辑表达式）、relExpr（关系比

4.2.3 SQL 语法实体设计 
针对语法解析器的顶层语法规则，需要设计对应的 Stmt 实体，以结构化的方式描述 SQL
查询语法的“骨架”。在 SQL 语义分析的过程中，系统通过构建器从每个语法类型中剥离具
体参数和条件式，获得查询语句对应的 StmtS 实体，以专注于 SQL 结构的转换，帮助开发人
员采用统一、精简的转换策略，维护语法和语义的正确性。 
为了更加细粒度地描述 StmtS 实体的语义信息，需要首先将待分析的语句内部属性抽象出
来，建立相应的语义模型。本节以简单 SELECT 为例，在标准 SQL 语句中，对应的 SQL 查
询块（query block）实体可以表示为一个五元组：

其中，WC 实体对应 where 子句，表示逻辑的、可嵌套的复合表达式，根据 4.2.2 节工作，

（1）Redis 语法实体设计 
KV 数据库是最简单的 NoSQL 数据库结构，其数据存储结构相对简单，数据以 key-value
的形式操作并存储在数据库中。以 Redis 为例，其键是字符串形式，其主体业务可以看做高效

Stmtkv = {< op, datatype, fields > | op ∈ OPkv ⋀ datatype ∈ DTkv} (4.14) 
其中，OPkv 表示 Redis 对键值对的 CURD 操作类型集合，包括获取、设置、删除等操作
类型，基本内容为： 
OPkv = {GET, MGET,SET, MSET, EXISTS,DEL} (4.15) 
DTkv 表示 Redis 支持的数据类型集合，通过与 OPkv 元素结合，共同描述更具体的 Redis

4.3.3 语义分析与验证 
当 Visitor 完成 AST 分析和元数据绑定后，返回的 StmtS 实体即可描述查询的逻辑结构，

⚫ 数据类型检查：确保列的数据类型是系统支持的，并且符合语法规则。

⚫ 唯一性检查：确保同一张表中没有重复的列名。

 问题描述 
在数据库结构迁移业务中，不同数据库系统（如 MySQL、Oracle、SQL Server 等）底层
原理、语法规范差异较大，在迁移过程中还需要将 SQL 方言重写为目标平台支持的形式。然
而，传统 RDB 之间的 SQL 转换方法通常依赖于字符串替换和正则表达式匹配，准确率低，
无法保证转换后的 SQL 逻辑，且映射模型扩展性差、难以维护；另一方面，在 RDB 向 NoSQL
数据库迁移业务中，迁移前后环境在数据模型与结构差异、查询语言、扩展性等方面存在更
大的差别，目前仍然缺乏高效、准确的迁移方案。因此，开发一套面向多源异构环境的、准
确、高效的语法重写转换器，是本文数据库结构和迁移方法研究中又一个关键任务。 
在上一章中，我们通过中间表示结构将 SQL 语句的语义信息从具体的语法细节中抽象出
来，使其更易于处理和转换。通过这种方式，我们可以将 SQL 语句的解析和转换过程与具体
的数据库方言解耦，使得整个系统更加灵活和可扩展。在本章，我们基于中间表示模型，编
写了一系列 SQL 方言转换方法，设计开发出了语法重写转换器，实现在不同的数据库系统之
间进行无缝的 SQL 语句迁移。 
 面向 SQL 方言转换的语法重写 
在 RDB 之间的迁移业务中，语法重写器负责接收语义分析器生成的中间表示实体，并针
对不同的源数据库和目标数据库，设计一套完善的语法重写转换规则。这些规则基于数据库
之间的语法差异和特性兼容性预编写，能够自动识别并转换逻辑执行结构中的方言内容，以
确保目标数据库的语法兼容性和功能完整性。 
5.2.1 SQL 语法重写转换流程

5.2.2 关键字转换方法 
不同的数据库系统可能使用不同的关键字来表示相同的操作。例如，要限制查询结果返回

5.2.3 数据类型转换方法 
当进行跨数据库系统迁移过程中，数据类型不一致是一个常见问题，因此重写转换器需要

⚫ 精度和范围：在转换为数值类型时，需要确保目标类型能够涵盖源数据的精度和范围。

⚫ 空值和默认值：在数据类型转换时，还需要考虑字段的空值和默认值问题。异构数据库对

处理。 
⚫ 长度限制：字符串类型的长度限制在不同数据库中可能有所不同。在转换时，需要确保目
标字段的长度能够容纳源数据，避免数据截断或溢出。

Redis 作为内存数据结构存储，用作数据库、缓存和消息代理，其本身允许存储的数据规

可以创建一个表，其中键是列名，值是数据。 
⚫ Set：集合中的每个元素可以转换为表中的一行。可能需要一个额外的列来存储元素的唯
一标识符（如果 Redis 的 set 中没有额外的信息来表示这一点）。 
⚫ ZSet (Sorted Set in Redis)：有序集合可以转换为包含分数和元素的两列的表。如果元素本
身具有结构，可以将其展开为多个列，并包括一个分数列。

现字符串拼接，当 CONCAT 函数的任何参数为 NULL 时，拼接结果将为 NULL。 
相较于SqlLines，G-Rewriter基于语义分析和元数据存储对于业务语句进行预处理和分析，
